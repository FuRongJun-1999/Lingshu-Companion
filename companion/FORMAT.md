# 对话 MD 格式契约 v1

> 这份文件定义 `data/interactions/*.md` 与 `data/relations/*.md` 的结构。
> **改这个格式 = 改解析器**，两边必须同时改。

---

## 一、为什么需要契约

Markdown 没有 schema。结构错了不会有异常，只会**静默解析失败**。
这份契约列出：**哪些不能动**、**哪些随便加**。

---

## 二、文件布局

```
data/
├── interactions/
│   └── YYYY-MM-DD.md      # 每天一个文件
└── relations/
    └── <safe_actor_id>.md # 每个观众一个文件
```

- 日期用**本地时区**
- `safe_actor_id` = 把 `: / \ 空格` 换成 `_`，保留中文

---

## 三、interaction block 结构

一个 block = 一次互动。**顺序固定**：

```markdown
<!-- id:9531d7c74db1 -->
## 20:14:30 · 小花 · bilibili:12345

- 类型：danmaku
- 状态：已回应

**观众**：

你好呀，今天讲什么

**她**：

今天讲记忆——为什么 AI 记不住你。

- 动作：看向弹幕、微笑、轻轻摇摆
- 情绪：happy
- 延迟：1240 ms

---
```

### 硬约束（改了会解析失败）

| # | 约束 | 说明 |
|---|---|---|
| 1 | 首行必须是 `<!-- id:<12位hex> -->` | 正则 `<!-- id:([0-9a-f]{12}) -->` |
| 2 | 第二行必须是 `## HH:MM:SS · 昵称 · 平台:ID` | 时间必须 8 字符；ID 段可省略 |
| 3 | `**观众**：` 与 `**她**：` 使用**全角冒号** | 半角冒号解析不到 |
| 4 | 字段内容前**必须有一个空行** | 正则按 `\n\n(.*?)\n\n` 抓取 |
| 5 | block 之间必须有 `---` 分隔 | 否则块边界判定失败 |
| 6 | `**她**：` 缺失 = 待回应 | 这是唯一合法的“未完成”状态 |

### 软约束（可自由增删）

| 项 | 说明 |
|---|---|
| `- 类型：` | danmaku / gift / console / idle / voice |
| `- 状态：` | 由是否存在 `**她**：` 推导，写错不影响解析 |
| `- 动作：` `- 情绪：` `- 延迟：` | 可缺省 |
| 任意 `>` 引用块 | 解析器忽略 |
| 任意额外的 `- xxx：` 列表项 | 解析器忽略 |

### 禁止

- ❌ 在 block 内插入第二个 `<!-- id:`
- ❌ 改动 id 的 12 位 hex 长度
- ❌ 把 `**观众**：` 写成 `**观众** :`（空格）
- ❌ 用 `###` 做小节标题（会与 `##` 冲突）

---

## 四、relation 文件结构

```markdown
# 小花

- ID：bilibili:12345
- 首次：2026-11-14 20:14
- 最近：2026-11-14 20:14
- 互动：1 次
- 亲密度：0.05

## 最近互动

- 2026-11-14 20:14 [danmaku] 你好呀，今天讲什么
```

### 硬约束

| # | 约束 |
|---|---|
| 1 | 首行 `# 昵称` |
| 2 | `- 互动：N 次`（正则依赖这个格式做自增） |
| 3 | `- 亲密度：0.00`（两位小数） |
| 4 | `## 最近互动` 之后每行 `- YYYY-MM-DD HH:MM [kind] 摘要` |

---

## 五、时间与时区

- 所有时间用**本地时区**
- 日期文件名 `YYYY-MM-DD`
- block 内时间只到秒，不含日期（日期取自文件名）

---

## 六、修改流程

改格式时必须同时改：

1. 这份 `FORMAT.md`
2. `store.py` 里的正则在 `_render_block` / `recent` / `recover`
3. `test_store.py` 的断言

**三者任一未改 = 静默数据损坏。**
